# Инструкция: коммерческая доработка `mebel-shop`

> Дополнение к `INSTRUCTION.md`. Базовый магазин уже собран (главная, каталог, карточка
> товара, корзина, checkout, контентные страницы). Здесь — коммерческое ТЗ: развёрнутый
> каталог, полная карточка модели, B2B и элементы доверия.
>
> **Объём намеренно сокращён:** всё делается на одном разделе каталога и одной карточке
> товара — как образец. Остальные разделы и товары остаются в текущем виде и работают
> ссылками-заглушками.
>
> Правила `INSTRUCTION.md` (стек, конвенции, палитра, `npm run lint`) в силе.
> Новых зависимостей не добавлять.

## 0. Границы объёма — читать первым

Делаем **только**:

| Что | URL | Файл |
|---|---|---|
| Каталог-хаб — две категории | `/catalog/` | `pages/catalog/index.vue` — существует |
| Раздел «Корпусная мебель» — 3 товара | `/catalog/korpusnaya-mebel/` | `pages/catalog/[slug]/index.vue` — существует |
| Одна карточка модели | первый товар листинга корпусной мебели | `pages/product/[slug]/index.vue` — существует |

В каталоге-хабе показываются **две** категории: «Корпусная мебель» и «Кухни» —
подкатегорий в каталоге намеренно мало. Остальные категории остаются в `db.json`
и открываются по прямым URL `/catalog/<slug>/`, но на хабе не выводятся.

Листинг корпусной мебели — **три товара**, этого достаточно, чтобы показать карточки,
фильтры и сортировку. Коммерческие блоки и полная карточка модели делаются только
для корпусной мебели; «Кухни» остаются в текущем виде и служат вторым превью.

**Не делаем:**

- верхнеуровневых URL `/kuhni/`, `/spalni/`, `/gostinye/`, `/prihozhie/`, `/shkafy/`,
  `/vannye-komnaty/`, `/mebel-na-zakaz/`, `/mebel/`;
- динамических страниц вида `pages/[category]/` и фильтр-лендингов `/kuhni/pryamye/`;
- отдельных страниц `/optovaya-prodazha/` и `/dlya-dilerov/` — B2B-блоки идут на
  существующую `/become-dealer/`;
- расширенных блоков на остальных карточках товаров — они остаются как есть.

Ссылки на разделы, которые не делаем, ведут на существующие категории `/catalog/<slug>/`.
Новых URL, кроме `/catalog/korpusnaya-mebel/`, не заводим.

### Жёсткие правила

1. **`routeRules` в `nuxt.config.ts` не добавлять.** Сопоставление URL и данных живёт
   в `routes.json` — так устроен проект. Конфиг Nuxt для этого не трогаем.
2. Новых файлов в `pages/` не создавать: работаем на существующих страницах.
3. Существующие URL не менять и не редиректить — ничего из работающего сломать нельзя.
4. Новые блоки рендерить через `v-if` по данным: категории и товары без этих данных
   должны выглядеть ровно как сейчас.

## 1. Данные: раздел и модель товара

### 1.1 Новый раздел в `db.json`

Ключ `korpusnaya-mebel` — по образцу существующих категорий (`kuhni`, `shkafy`):

```jsonc
{
  "seo":    { "h1": "Корпусная мебель от производителя", "title": "…", "meta": [], "canonical": "" },
  "schemaOrg": [],
  "breadcrumbs": [
    { "url": "/", "label": "Главная" },
    { "url": "/catalog/", "label": "Каталог" },
    { "url": "/catalog/korpusnaya-mebel/", "label": "Корпусная мебель" }
  ],
  "category": { "slug": "korpusnaya-mebel", "url": "/catalog/korpusnaya-mebel/", "collections": [] },
  "intro": "коммерческое вступление 500–1000 знаков",
  "filters": [], "sortOptions": [], "products": [], "pagination": {}
  /* + поля блоков из §3 */
}
```

Состав: **три товара** из категории `shkafy` — карточки берутся в том же усечённом виде,
что и в других категориях листинга. `category.collections` — ссылки на существующие
категории (`/catalog/shkafy/`, `/catalog/tumby/`, `/catalog/stoly-i-stulya/`),
не на несуществующие лендинги.

В ключе `catalog` → `categories` оставить **две** карточки: `korpusnaya-mebel` первой
и `kuhni` второй. Остальные категории из массива убрать — их данные остаются в `db.json`
и доступны по прямым URL.

Фильтры собирать по фактическому составу раздела: опции без товаров и группы
с единственным значением не выводить.

### 1.2 `routes.json`

Одна строка:

```json
"/catalog/korpusnaya-mebel/": "/korpusnaya-mebel/"
```

Больше ничего. Хендлер `server/api/catalog/[slug]/index.get.ts` уже есть и работает.

### 1.3 Расширение модели товара

`interfaces/product/IProduct.ts` — добавить полям **опциональность**, чтобы товары без них
не ломали типы:

```ts
style?: string             // 'Современный' | 'Классический' | 'Скандинавский' | 'Лофт' | 'Неоклассика'
constructionType?: string  // 'Шкаф-купе' | 'Распашной' | 'Угловой' | 'Модульная' | 'Прямая'
bodyMaterial?: string      // материал корпуса
facadeMaterial?: string    // материал фасадов
purpose?: string           // назначение: 'Для гостиной', 'Для спальни'…
dimensions?: { width: number; depth: number; height: number } // мм, для фильтра по размеру
availabilityType?: 'in-stock' | 'made-to-order'
productionDays?: number | null // срок изготовления в днях
priceFrom?: boolean        // true → цена выводится как «от 118 700 ₽»
```

Проставить эти поля товарам раздела `korpusnaya-mebel` (в категориях-источниках
и в их страницах товара). Остальным товарам — по желанию, на работу не влияет.

### 1.4 Поля карточки модели

Отдельный интерфейс `IProductDetails extends IProduct` — всё, что показывается только
на странице товара, все поля опциональны:

```ts
setContents?: { label: string; value: string }[]    // состав комплекта
filling?: { label: string; value: string }[]        // внутреннее наполнение
hardware?: { brand: string; description: string }[] // фурнитура
finishes?: { label: string; colorHex?: string; priceDiff: number }[]
modifications?: string[]                            // допустимые изменения конструкции
configurations?: { title: string; img: IImg; description: string; priceDiff: string }[]
priceFactors?: { title: string; text: string }[]    // из чего складывается цена
productionTerm?: string                             // '22 рабочих дня'
warranty?: { term: string; text: string }
deliveryPrice?: { title: string; value: string }[]  // доставка / сборка / подъём
liftingTerms?: string
orderSteps?: { step: number; title: string; text: string }[]
files?: { title: string; url: string; size: string; type: 'pdf' | 'dwg' | '3d' }[]
video?: { url: string; preview: IImg } | null
```

Заполняются **только у одного товара** — первого в листинге корпусной мебели.
Правило: если цена зависит от конфигурации — `priceFrom: true` и обязательный блок
`priceFactors`, иначе страница коммерчески пустая.

## 2. Фильтры и сортировка

`stores/storeCatalogFilters.ts` — расширить `ICatalogFiltersState`:

```ts
style: string[]
constructionType: string[]
bodyMaterial: string[]
facadeMaterial: string[]
availability: string[]                 // 'in-stock' | 'made-to-order'
widthFrom / widthTo: number | null
heightFrom / heightTo: number | null
```

- `MULTI_KEYS` дополнить новыми массивами, синхронизация с query — по существующей схеме.
- Сортировка: `popular`, `new`, `price-asc`, `price-desc`, `discount`, `rating`.
- `CatalogFilters.vue`: группы-аккордеоны (`UIAccordion`), счётчики у опций, «Сбросить всё»,
  на мобиле — в `UIModal` с кнопкой «Показать N товаров».
- Группы фильтров строятся по тем полям, которые есть в товарах раздела: пустые группы
  не показывать — иначе на старых категориях появятся пустые аккордеоны.
- Комбинации фильтров живут в query и получают `<meta name="robots" content="noindex, follow">`;
  индексируется только чистый URL раздела.

В карточке листинга (`ProductCard.vue`): цена или «от», наличие либо срок изготовления,
размеры, свотчи цветов, кнопки «В избранное», «Сравнить», «Быстрый заказ».
Всё новое — через `v-if`, старые категории не должны измениться.

Над листингом или в его конце — блок «Не нашли подходящее? Запросите консультацию»
с кнопкой, открывающей `ModalConsult` (§5): по ТЗ возможность запросить консультацию
должна быть в самом каталоге, а не только в плавающих кнопках.

## 3. Категорийная страница `/catalog/korpusnaya-mebel/`

Блоки рендерятся в `pages/catalog/[slug]/index.vue` по `v-if` на соответствующие поля
`db.json`. Компоненты — в `components/Category/`:

1. Хлебные крошки и `h1` — уже есть в `CatalogHeader`.
2. `CategoryIntro` — коммерческое вступление 500–1000 знаков + CTA «Рассчитать стоимость».
3. `CategorySubcategories` — плитки подкатегорий (ссылки на существующие категории).
4. `CatalogListing` — фильтры, сортировка, сетка, пагинация (есть).
5. `CategoryCalcUnit` — форма быстрого расчёта → `/api/calculate-project/` (эндпоинт есть).
6. `CategoryAdvantages` — преимущества заказа у компании.
7. `CategoryMaterials` — материалы корпуса и фасадов, фурнитура.
8. `CategoryStages` — этапы изготовления: замер → проект → согласование → цех → монтаж.
9. `CategoryDelivery` — доставка, сборка, подъём и цены.
10. `CategoryWarranty` — гарантия и сервис.
11. `CategoryProjects` — фото реализованных проектов (`useGLightbox`).
12. `CategoryFaq` — 6–10 вопросов, `UIAccordion` + schema.org `FAQPage`.
13. `CategoryLinks` — перелинковка на смежные категории и услуги.

Тексты — в `db.json` под ключом `korpusnaya-mebel`, отдельным полем на блок.
Стиль и анимации — как на главной, `prefers-reduced-motion` уважаем (§11 `INSTRUCTION.md`).

## 4. Карточка модели — одна штука

Первый товар листинга корпусной мебели доводится до коммерческого ТЗ, остальные остаются
как есть. Все новые блоки — через `v-if`, чтобы товары без данных не ломались.

- `ProductGallery` — минимум 5 кадров: общий вид, фасады крупно, фурнитура, внутреннее
  наполнение, интерьер; лайтбокс. Если у модели заполнено поле `video` — первым слайдом
  идёт превью с иконкой воспроизведения, ролик открывается в том же лайтбоксе.
- `ProductInfo` — назначение и стиль, цена или «от», наличие либо срок изготовления,
  размеры, материал корпуса и фасадов, свотчи отделки с пересчётом цены, кнопки
  «В корзину», «Купить в 1 клик», «Рассчитать стоимость», «Задать вопрос», избранное
  и сравнение; ниже — гарантия, доставка, сборка, подъём, срок ответа менеджера.
- `ProductTabs` — Описание · Характеристики · Состав комплекта · Наполнение · Фурнитура ·
  Возможные изменения · Доставка и сборка · Гарантия · Отзывы.
  Вкладка «Фурнитура» выводит `hardware`: бренд и что именно за узел отвечает —
  по ТЗ это отдельный пункт карточки модели, а не строка в характеристиках.
- Новые компоненты: `ProductConfigurations` (варианты конфигурации с фото и объяснением,
  что влияет на цену), `ProductPriceFactors`, `ProductOrderSteps`, `ProductFiles`,
  `ProductRequestForm` («Получить расчёт»), `ProductStickyBar` (моб.).
- schema.org: `Product` + `Offer` (`price`, `priceCurrency`, `availability`) +
  `AggregateRating` + `BreadcrumbList`.
- `ProductRelated` — уже есть, оставить.

## 5. Коммерческие элементы и B2B

Без новых страниц:

- `AppHeader`: телефон, «Заказать звонок», акцентная кнопка «Рассчитать стоимость»,
  «Скачать каталог».
- `AppFloatingActions` — мессенджеры (WhatsApp, Telegram) и онлайн-консультация,
  фиксированы справа снизу; ссылки из `general` в `db.json`.
- Модалки на `UIModal` + `vue-final-modal`: `ModalCallback`, `ModalQuickOrder`,
  `ModalCalcPrice`, `ModalPriceRequest`. После отправки — `UIToast` и «ответим в течение
  15 минут в рабочее время».
- Блок доверия: сертификаты, фото производства, счётчики, отзывы клиентов и дилеров.

**B2B — на существующей `/become-dealer/`.** ТЗ просит отдельный раздел для дилеров;
в сокращённом объёме он делается одной страницей — это осознанное отступление, при
расширении объёма раздел разносится на `/optovaya-prodazha/` и `/dlya-dilerov/`.
Страница должна отрабатывать коммерческие запросы «корпусная мебель оптом»,
«мебель от производителя для дилеров», «поставщик корпусной мебели» — эти формулировки
идут в `h1`, `title`, `description` и в текст блоков.

Добавить блоки: условия оптовой работы,
минимальная партия или сумма, дилерская скидка сеткой, складская программа, сроки
производства, территория поставок, упаковка, рекламационная политика, гарантийные
обязательства, 3D-модели и чертежи, фотобанк для магазинов, отзывы дилеров, форма заявки
(есть) и блок прайс-листа: «Скачать» + «Прислать на e-mail»
(`server/api/price-request/index.post.ts`). Файлы-заглушки — в `public/files/`.
