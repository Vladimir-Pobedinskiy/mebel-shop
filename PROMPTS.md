# Промпты по этапам

Порядок запусков для сборки проекта. Один запуск = один блок этапов из §12 `INSTRUCTION.md`.
Между блоками — `/clear`, иначе контекст забивается и качество падает.

Старт сессии:

```
cd d:\web\my_works\mebel-shop
claude
/add-dir d:\web\my_works\alternative
```

---

## 1. Каркас и данные (этапы 1–4)

```
читай INSTRUCTION.md и начинай с этапов 1–4 (каркас, стили, инфраструктура, данные).
db.json наполни реально: 8 категорий и минимум 30 товаров.
в конце запусти npm run double и покажи, что /api/home/ отдаёт данные. дальше не иди
```

Проверить самому: `http://localhost:3001/api/home/` отвечает, `npm run dev` поднимается без ошибок.

## Что помогает

- **`/clear` между блоками.** Инструкция перечитывается заново — это дешевле, чем тащить
  контекст предыдущего этапа.
- **«дальше не иди» / «страницы не трогай».** Без явной границы агент уходит в следующие
  этапы и выдыхается на середине.
- **Правки — сразу, пока этап свежий.** «переделай hero: заголовок крупнее, убери параллакс»
  в том же запуске дешевле, чем возврат к нему через три этапа.
- **Проверять вживую после блоков 1, 3, 5.** Это точки, где ошибка архитектуры дорого
  обходится позже.
- **Просить честный отчёт.** «что не доделал — скажи прямо» в конце каждого блока.
- **Ревью перед финалом:** `/code-review` по изменениям, или `/code-review ultra` для
  глубокой проверки всей ветки.
